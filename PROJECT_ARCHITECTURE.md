# Архитектура проекта — Система рецензирования документов (MVP)

## Краткое описание продукта

Серверная часть системы рецензирования документов. Автор создаёт заявку на рецензирование и прикрепляет документ. Рецензент берёт заявку в работу, проверяет документ, оставляет комментарий и либо отправляет на доработку, либо утверждает. Автор вносит исправления и загружает новую версию. Админ управляет учётными записями, может открепить/назначить рецензента и удалить заявку.

В MVP не входят: фронтенд, реальное хранилище файлов (S3 и аналоги), внешняя аутентификация (vk_id и аналоги). Хранилище файлов вынесено за границу продукта, поэтому MVP хранит только метаданные/ссылки на документы.

## Роли и полномочия

| Роль      | Доступно                                                                          | Недоступно                                                     |
|-----------|-----------------------------------------------------------------------------------|----------------------------------------------------------------|
| Автор     | Создавать заявки, загружать исправленные документы, просматривать свои заявки и комментарии | Просмотр чужих заявок, рецензирование, утверждение, функции админа |
| Рецензент | Забирать свободные заявки, оставлять комментарии, отправлять на доработку, утверждать документы | Просмотр заявок, не взятых в работу, создание заявок, функции админа |
| Админ     | Создавать учётные записи, откреплять/назначать рецензента, удалять заявку          | Создание заявок, рецензирование                                 |

Неавторизованные пользователи не имеют доступа.

## Модель данных

### Пользователь (User)
- Id (GUID)
- Имя/логин (уникально)
- Хэш пароля + соль (хранятся; вход через JWT)
- Роль: Author | Reviewer | Admin
- CreatedAt

### Заявка (ReviewRequest)
- Id (GUID)
- AuthorId (User)
- Заголовок / описание (текст)
- DocumentReference (ссылка/идентификатор файла во внешнем хранилище; в MVP — ссылка или плейсхолдер)
- Status: `Draft | Submitted | InWork | InRework | Approved`
- AssignedReviewerId (User, nullable — ставится при взятии в работу)
- CreatedAt, UpdatedAt

Жизненный цикл заявки:
- Создание автором → `Submitted`
- Рецензент берёт в работу → `InWork`
- Рецензент отправляет на доработку с комментарием → `InRework`
- Автор загружает новую версию → обратно в `InWork` (по описанию сценария — «в работе»)
- Рецензент утверждает → `Approved`

### Версия документа (DocumentVersion)
- Id (GUID)
- ReviewRequestId
- FileReference / метаданные (uri, имя файла, размер, media-type — плейсхолдер)
- UploadedBy (User)
- UploadedAt
- У заявки может быть несколько версий за цикл рецензирования.

### Комментарий (Comment)
- Id (GUID)
- ReviewRequestId
- AuthorId (кто написал комментарий — обычно рецензент)
- Text
- CreatedAt

Комментарий привязан к заявке. В сценарии рецензент оставляет комментарий и отправляет на доработку; автор просматривает комментарии. Вынесено в отдельную сущность для удобства истории.
