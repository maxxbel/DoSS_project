## Границы доверия

| Граница | Что пересекает | Почему требуется проверка |
| --- | --- | --- |
| Клиент <-> Сервер | Автор, рецензент, админ. Документы, персональные данные, заявки, комментарии | Аунтификация не гарантирует безопасности, учётная запись или auth-токен могли быть украдены |
| Сервер <-> Внешнее хранилище данных | Ссылки, имена, метаданные, файлы, результаты обращения к файлам | Файлы могут быть заражены, сервис может быть скомпрометирован |
| Внутренняя граница: API <-> Сервис предметной области | Запросы и параметры | Даже если слой API пропустил запрос это не значит, что он не приведёт к несогласованности модели предметной области. Модель должна проверить, существует ли файл, заявка, имеет ли пользователь право на взаимодействие с объектом и т. д. |

## Угрозы

| ID | Сценарий угрозы | Что нарушается | Граница / точка входа | Связанные SR | Приоритет и обоснование |
| --- | --- | --- | --- | --- | --- |
| T-01 | Автор, рецензент получают доступ к чужому ресурсу путём подмены параментров запроса | Ограничение доступа к заявкам | Граница API <-> Сервис предметной области | SR-01, SR-02 | Высокий, возможна утечка чувствительной информации из заявки, документа |
| Т-02 | Автор, рецензент получают доступ к административным функциям | Ограничение доступа к административным функциям | Граница Клиент <-> Сервер | SR-03 | Высокий, администратор имеет право на просмотр всех заявок, документов, возможность создавать учётные записи. Получение несанкционированного доступа к этим функциям приведёт к утечке всех данных |
| Т-03 | Неаунтефицированный пользователь получает доступ к функциям системы | Ограничение доступа к функциям системы для неаунтефицированных пользователей  | Граница Клиент <-> Сервер | SR-04 | Средний, некоторые функции выдают чувствительную информацию в своих ответах |
| T-04 | Неаунтефицированный пользователь получает доступ к учётной записи путём перебора возможных логина и пароля | Ограничение доступа к функциям системы для неаунтефицированных пользователей | Граница Клиент <-> Сервер | SR-04, SR-05 | Высокий, утечка учётной записи администратора открывает путь для получения всех данных системы |
| Т-05 | Автор, рецензент получает доступ к функциям не своей роли (не административным) по своим заявкам | Разграничение функций по ролям | Граница API <-> Сервис предметной области | SR-06, SR-07 | Средний, рискуется нарушение согласованности модели, утечки информации не возникает. Возможно утверждение нерецензированного документа |
| T-06 | Над заявкой совершается действие (автором, рецензентом), недопустимое из-за статуса | Ограничение функций по статусу заявки | Граница API <-> Сервис предметной области | SR-08, SR-09, SR-10 | Средний, рискуется нарушение согласованности модели, возможна потеря данных. |
| Т-07 | Злоумышленник получает доступ к внешнему файловому хранилищу | Ограничение доступа для неаунтефицированных пользователей | Граница Сервер <-> Внешнее хранилище данных | --- | Средний, возможна подмена файлов на заражённые, утечка чувствительной информации из документов. |
